# Minimal judgment-fixture template

三条样例，演示「可复算的判据 + 必失败的负控 + 缺字段不等于零」。

| 文件 | 作用 |
|---|---|
| `judgments.example.jsonl` | 判据清单，一行一条。`criterion_version` 必填，同批不许混版本 |
| `run_judgments.py` | 跑批器。退出码：0 全绿 / 2 正向失败 / 3 负控不红（整套不可信）/ 4 版本问题 / 5 自检失败 / 6 缺字段 |
| `README.md` | 就是本文件 |

## 怎么换成你自己的

1. 把 `total_of()` 换成你的「观测函数」：**只从实际存在的字段算，缺字段返回 None，绝不返回 0**。
2. 把 `check()` 的期望值来源限定为：**域外签发的常量**或**从冻结原始字节独立重算**。被测进程里算出来的期望值一律不接受。
3. 每条正向判据配一条 `"control": "negative"` 的配对负控，`expect` 故意写错，期望它 FAIL。
4. 跑 `python3 run_judgments.py`；再跑 `python3 run_judgments.py --selftest`。

## 三条容易漏的

- **负控不红 → 判「整套不可信」，不是判通过。** 这是负控和普通失败的区别。
- **`--selftest` 和负控不是一回事。** 负控证明「判据能红」，selftest 证明「检查器本身能红」。
- **缺字段 ≠ 零。** 观测里没有这个键要判 `UNKNOWN_MISSING_FIELD`，不许 `.get(k, 0)`。

## 真实场景请补两件事

- **黑盒执行**：把被测代码复制到临时目录、用子进程跑、只读落盘产物，不要 `import` 被测模块——否则被测代码里一个 `except` 就能把红变绿。
- **回滚验证**：把守卫/判据对应的那行代码临时改回错的，**必须变红**；还绿说明没覆盖到那条路径。
